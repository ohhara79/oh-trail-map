# Esc leaves 3D for 2D

## Context

In 3D, Esc stepped back from playback to walk and then to orbit (`src/view3d.ts`). In orbit it went on to `src/ui.ts`, which cleared the filter, then the selection, then closed the panel. After that, Esc did nothing, so the only ways back to 2D were the 3D button and `3`. Esc should get you back to 2D too.

## Change

2D goes at the end of the existing chain, which keeps the "most local thing first" rule. In 3D the chain is now: playback → walk → orbit → filter → selection → panel → 2D.

1. `src/ui.ts`: `UiCallbacks` gains `onEscape`. The Esc listener closes the panel only when it is open. Otherwise it calls `onEscape`.
2. `src/main.ts`: `onEscape` calls `close3d()` when the 3D view is open. In 2D it does nothing, as Esc did before.
3. `src/view3d.ts`: the comment on `onKeyDown` now says the chain ends in 2D.
4. `index.html` shortcut sheet and `README.md`: Esc's step-back list now ends in 3D.

The `?` sheet's capture listener still takes Esc first, so closing the sheet never drops you out of 3D.

## Verification

1. `npm run build` passes.
2. 2D: Esc still clears the filter, then the selection, then closes the panel. With all of those clear, it does nothing.
3. 3D orbit with no selection and the panel closed: Esc returns to 2D at the spot 3D was looking at.
4. 3D from Enter on a selected trail: Esc goes to walk, then orbit, then clears the selection, then returns to 2D.
5. 3D orbit with the panel open: the first Esc closes the panel, and the second returns to 2D.
6. With the `?` sheet open in 3D, Esc only closes the sheet.
