# Keep both 다사49293899 rows, keyed by region, drawn 10 m apart

## Context

`data/national_points_w_name.tsv` files 다사49293899 twice: once under 서울특별시 금천구
(named 호압사 갈림길), once under 경기도 안양시 만안구 (no name). It is one sign on the
boundary. `parseNationalPoints` dropped the second row (first row wins), so the points list
showed one row and the map one pin. The reason was that the 지점번호 was the identity
key everywhere: the hidden set in Settings, the selection, list rows, the 2D markers, the
3D GeoJSON filter, and the profile's passes. Both rows should be shown.

Two problems follow from that:

- **Identity.** A 지점번호 alone no longer identifies a row. The key becomes 시/도 + 시/군/구
  + 지점번호. It depends on what a row says rather than where it sits in the file, so
  reordering the TSV can never move a hidden flag onto the other row.
- **Position.** Both rows decode to one grid position, so their pins would stack and the
  lower one could never be seen or clicked. They are drawn a little apart. The printed
  coordinates stay the true decoded position, which is the same for both rows: the offset
  exists only on screen.

## Change

1. **`src/nationalPoint.ts`**
   - `NationalPoint.id` is `pointId(province, district, code)`, space-joined.
     `parseNationalPoints` dedups on `id` rather than on `code`. A repeat under the same
     region still says nothing new and is still dropped.
   - `gridLat`/`gridLon` hold the true decoded position. `lat`/`lon` are now documented as
     the *drawn* position.
   - `spreadRepeats` groups points by `code` and places each group of more than one
     evenly on a circle with a 5 m radius (`REPEAT_SPREAD_M`), the first point due east. For
     the pair this means 10 m apart, east and west of the centre. 5 m is half the grid's
     10 m unit, so neither pin leaves the cell its code names. Every other point has
     `lat === gridLat`.
2. **Identity: `code` → `id`.** This covers `PointRow.id`, the marker map, `setHovered`
   (`src/points.ts`), `data-point-id`, `renderedIds()`, and the callbacks
   (`src/pointsList.ts`). In `src/main.ts` it covers `pointById`, `selectedPointId`,
   `setPointsHidden`, and the stepping and toggling of all points. The same switch applies
   to the pass pins and `pointAt` in `src/profilePanel.ts`, the feature property and
   `pointsFilter` in `src/scene3d.ts`, and the skip, hidden and pick checks in `pointDots.ts`,
   `pointBalls.ts` and `view3d.ts`. Every remaining `.code` is shown to the user (list title,
   popup, hover label).
3. **Printing.** `formatLatLon` (`src/points.ts`) reads `gridLat`/`gridLon`, so the list and
   the popup print the same position for both rows. Everything that draws or aims (pins, the
   popup anchor, fly-to, `pinAt`, 3D dots, balls and walk sighting) keeps reading `lat`/`lon`.
4. **Migration** (`src/main.ts`, where `hiddenPoints` is built). A saved bare 지점번호 that is
   not an id expands to the ids of every point with that code, and the result is saved
   back. Nothing a user hid comes back into view. A key that matches nothing is kept, as it
   always was. This lives in `main.ts` because `store.ts` has no point list.
5. The checkbox aria-label reads `Show ${row.title} on map`, so the two rows' labels differ.
